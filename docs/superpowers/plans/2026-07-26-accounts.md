# Accounts & Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the anonymous license-key entitlement with a GitHub-account entitlement, served by a unified Next.js-on-Cloudflare app sharing the existing D1, and refactor the VS Code extension to sign in with GitHub instead of pasting a key.

**Architecture:** A single Next.js app deployed to Cloudflare Workers (via `@opennextjs/cloudflare`) binds the same D1 database. All account logic lives in **framework-agnostic modules** under `web/src/server/**` with the same `(request, deps)` handler shape as the v1 Worker, so it is tested with `@cloudflare/vitest-pool-workers` (Miniflare) exactly as v1 was. Next.js `app/api/**/route.ts` files are thin adapters that inject the D1 binding from `getCloudflareContext().env`. Auth.js (`next-auth@beta`) handles only the browser OAuth cookie flow; the extension authenticates by silently re-fetching its VS Code GitHub session token and POSTing it to `/auth/github` and `/auth/refresh`. The existing Ed25519 token machinery is reused unchanged; only `sub` changes from `sha256(licenseKey)` to `accountId`.

**Tech Stack:** Next.js 15 (App Router), `@opennextjs/cloudflare`, Cloudflare Workers + D1, Wrangler, `next-auth@beta` (GitHub provider, JWT sessions), `@cloudflare/vitest-pool-workers` (backend tests), Ed25519 via Web Crypto, Paddle Billing webhooks; extension side TypeScript + `node:test` + esbuild.

## Global Constraints

- **Token lifetimes (verbatim):** 7-day TTL, 14-day offline grace (from token `iat`), **daily recheck on local calendar-day boundary, non-blocking**. Recheck must never be awaited in the extension activation path and must add zero startup latency; `isPro()` is offline + synchronous against the cached token.
- **Entitlement token:** Ed25519 (`alg:"EdDSA"`), payload `{ sub: accountId, deviceId, status, plan, iat, exp }` in **seconds**, `exp = iat + 7d`. Reuse `web/src/server/lib/jwt.ts` (ported from `server/src/lib/jwt.ts`) unchanged.
- **Secrets — never commit values** (`.dev.vars` is gitignored): `GITHUB_OAUTH_CLIENT_ID`, `GITHUB_OAUTH_CLIENT_SECRET`, `AUTH_SECRET`, `LICENSE_SIGNING_PRIVATE_KEY`, `PADDLE_WEBHOOK_SECRET`. The throwaway TEST signing key in the Vitest config is the one allowed committed exception.
- **Bearer secrets:** GitHub tokens and entitlement tokens are bearer secrets — **never log their values**.
- **Identity join key** is the numeric GitHub `id` (`github_id`), never the mutable username.
- **Device limit** = 3 distinct `device_id`s per account (unchanged from v1). Re-activating the same device is idempotent (no new slot).
- **Consent:** `marketing_consent` is an **unticked opt-in** (default 0). Marketing use requires it; service operation does not.
- **Webhook replay protection:** event-id dedupe via `processed_events` (check-first, record-last) — carried over from v1 unchanged.
- **Paddle field paths & signature scheme** must be verified against live Paddle docs before go-live (human step) — the code mirrors the v1 verified scheme.
- **Scope boundary:** This plan builds the accounts *foundation* — data model, both auth front doors, the account-scoped endpoints, the webhook rework, and the extension refactor. **Dashboard pages/UX, the free DIY bot, and the managed relay are separate sub-projects** (#2–#4) and are out of scope here. Task A10 stands up web login only far enough to prove the session mechanism.
- **Clean cutover:** nothing is deployed live (no production keys issued), so v1 `licenses`/`activations` are dropped, not migrated.

import GitHub from "next-auth/providers/github";
import { getCloudflareContext } from "@opennextjs/cloudflare";
import { upsertUserByGithub } from "@/server/account/repository";

export async function upsertOnSignIn(profile: { id: number; login: string; name: string | null; email: string | null; avatar_url: string | null }, db: D1Database, now: number): Promise<string> {
  const u = await upsertUserByGithub(db, { githubId: profile.id, email: profile.email, name: profile.name, username: profile.login, avatarUrl: profile.avatar_url }, now);
  return u.id;
}

export const { handlers, auth, signIn, signOut } = NextAuth({

  providers: [GitHub],
  callbacks: {
    async jwt({ token, profile }) {
      if (profile) {
        const { env } = getCloudflareContext();
        token.accountId = await upsertOnSignIn(profile as any, env.DB, Date.now());
      }
      return token;
    },
    async session({ session, token }) {
      (session as any).accountId = token.accountId;
      return session;
    }
  }
});
